- 本机 RTX 4070 Laptop；GPU 批量推理已经启用。

## 第一轮 A：同轨迹跨阶段 policy 缓存

### 实现范围

先限于 `ramen_root_bench` 的 GPU 波次 rollout 后端，使用独立开关，默认关闭。缓存属于单条轨迹，不能放在跨轨迹共享的训练员里；不做全局缓存或内容索引。CPU 参考路径保持不变。

### 命中条件及不变量

1. 仅复用同一轨迹、同一回合，上一决策为 RamenSelect、当前为 SpecialSelect 的 policy；模型和推理配置在运行期间冻结。
2. 仍执行现有 prepare_decision，保留守门、单候选处理、Canonical 编码和合法性校验。只有真正进入 NeedsInference 时才检查缓存。
3. 比较实际编码的全部 754 个 f32 位模式；不使用容差近似或哈希。非有限输入不得视为缓存命中，应沿既有错误路径处理。
4. 只复用 policy 输出，必须以当前合法候选及顺序重新调用生产 resolve_decision；不能复用上一动作下标、掩码或候选分数。
5. 不推进 RNG；缓存不跨轨迹重置、回合、模型变更或不满足约束的中间决策。终局及轨迹槽位复用时清空；事件/Resolved 路径的缓存生命周期必须明确且保守。
6. 缓存失配正常推理，推理错误不得回退手写。复用仍走原动作落地与“答案恰好消费一次”检查。

记录 eligible、hits、misses（原因）、实际 GPU 请求、复用决策数。对拍 trace 必须保留缓存命中的逻辑决策，不能只记录真实推理请求从而漏掉动作差异。

## 第一轮 B：按根选择物理 batch

使用独立开关，默认保持固定 batch=512；同一侧车、同一份模型常驻，不为换 batch 重启进程或复制模型实例。

- 第一版只按根选择，不实施每波次动态扩缩、双缓冲或复杂自调优。
- 初始有限档位为 256／512／1024；以根上候选数 × n 选择，使用不超过总 rollout 数的最大档，低于 256 时使用 256 并报告补零。保留固定档模式以便对照；这只是待测启发式，不宣称最优。
- 明确调度器 active 轨迹容量与 GPU 物理张量 batch 是两个概念。按根选出的容量在本根内固定，尾部照常补零；缓存命中后没有任何待推理行时直接继续调度，不发送空推理。
- Rust/Python 协议必须明确本根的物理 batch；现有双 u32 头的含义不得单侧重解释。必要时加显式控制消息/协议版本，两端同步校验，并保留固定模式。
- 每个使用档位预热后再开始计时；持久缓冲区可以按档位复用，不改变数值精度。检查短读、截断、越界、不完整消息、输出行数、EOF、stderr 排空。
- 记录每根选定档位、有效请求、实际物理格位与填充率；格位数按实际档位累加。没有 GPU 请求的根单列 N/A，不能用“0% 填充率”证明浪费。

## 验证与归因

1. 改动前先保留可运行基准入口与实际命令、配置、权重路径、软件版本；直接核对文件，禁止 hash。旧日志只作参考，性能比较应在同一时段重测基线。
2. 四臂：基线（无缓存、B512）、仅 A、仅 B、A+B。先 A 对拍及计时，再 B，最后组合；不能只给最终加速比。
3. 固定根沿用探索性面板：plan0、seed61444、run1200，t6 RamenSelect／t30 Train／t47 RegionSelect。必须核实实际命中回合、阶段及候选数。该面板用于性能，不作为新盲测。
4. 小 n 正确性先行：按 candidate/j/seed 逐项对齐全部 score、score_pt；逐逻辑决策比较 turn、stage、候选原顺序、输入、选中动作。候选最终排序键和最佳动作也要比较。
5. 缓存覆盖：正常命中、输入任一位改变、换回合、换轨迹、槽位复用、缺前项、Resolved/事件路径、单候选、无待推理行。batch 覆盖：边界、小根、尾批、跨根切换、重复请求及协议错误。新增针对性测试，按项目 Checks/Result/println 规范；不跑全量测试。
6. FP32 和权重不变不保证不同物理 batch 永远逐位一致。报告输出最大误差及动作分歧，不能只报容差通过。本轮零动作/轨迹分歧为验收门槛；发现分歧就停下分析，不提高容差或删样本使之通过。有限测试不构成全局等价证明。
7. 性能 n=256、workers=24，关闭逐决策记录，各臂至少三次，交错串行运行（不同时跑两个性能任务）。报告中位数/范围、CPU 段、侧车往返、请求/命中数、物理格位、显存、失败数，加载预热单列。
8. 固定根通过后，生产教师接线跑基线与 A+B 同一探索性完整局，all 搜索阶段、All 地区策略。比较全部逻辑动作及终局 score/score_pt。报告真实整局墙钟；一对整局耗时仅作确认，不估计棋力或稳定加速区间。
9. 没有稳定收益的优化不默认启用；缓存少了请求也不等于墙钟一定同比下降。收益不直接相加。不影响正式数据采集。

## 第二阶段：继续等价性能优化（待 review 后选择）

按剩余耗时而非预定清单决定，先测再改，每次保持可关闭的参考路径：

1. **policy-only 返回、缓冲与序列化优化。** 先测 CPU/管道成本；仅减少返回值不会自动省掉整个前向。若裁剪模型输出算子，需要单独核对 policy 数值，不能顺带改变集成方式或正式 ONNX 契约。
2. **GPU 前向 profiler。** 定位小 kernel 启动、分配和同步后，再讨论执行图捕获或编译优化；固定模型、FP32、不启 TF32。不同执行顺序可能改变浮点结果，重新进行输出及轨迹对拍，不承诺逐位不变。
3. **CPU/GPU 重叠。** 在稳定单流实现上评估，分开管理每轨迹状态与随机流，按 candidate/j/seed 归还结果；不得因异步完成顺序改变抽样或聚合顺序。收益上限受可隐藏的 CPU 时间限制。

没有稳定收益就停止该分支；不把若干百分比收益简单相加，不预先承诺数量级提速。后续量化、低精度、减少集成成员或改模型结构属于效果可能变化的另一类实验，不混入等价优化。

### C：地区组合预筛选，建议优先探索

用户原始设想：第一年用手写；第二、三年只搜索 NN 排名前三的组合。必须完整保留这项想法，但第一年切换与 top-k 分臂测试，不捆绑归因。

- top-3 指**三个不同的合法三地区组合**：枚举组合，按三个地区 policy logits 之和排序；不是选三个地区后得到唯一一个组合。并列时用明确且稳定的顺序处理。
- 先用现有完整候选地区数据离线测 top-3/5/10 的最佳候选覆盖率与保留后悔值：全体最佳参考效用减去保留集合内最佳参考效用。按年份、马娘、构成分别报告，也看严重遗漏和尾部损失，不能只看命中率。
- 多热加和头有交互表达局限；它排除的组合即便很好也无法被后续搜索救回。现有标签是旧教师口径，筛查通过不等于 NN rollout 口径也通过。
- 首个可选保护臂：NN 前三组合与手写推荐组合取并集，去重后最多四个；全候选路径保留。先确定手写推荐取自同一局面、其 RNG 副作用如何隔离。
- 第二年 10→3、第三年 120→3 是候选续跑数量降幅，不等于实际耗时或整局降幅；候选减少会降低 batch 填充率。分别测固定每候选预算及固定总算时，不能混称同预算。
- 用作教师采集时保留一部分全候选探索/审计根，比例待定。未搜索的合法动作不能标成非法，缺失评分不能伪装成零收益或零优胜概率；如现有训练 loader 无法区分“未评估”和“已评估”，先解决训练口径再混训，不能静默产出自我强化的标签。
- 第一年的“改手写”是独立策略变更；现有三年合换的地区收益不能证明第一年 NN 无价值。

### D：短程 rollout + NN value 叶估值

> **状态（2026-09-17）：已执行两轮（固定根试点 + 保守混合路由筛查）。**
> 本小节以下文字是**原计划**，保留不改；实际做到哪一步、测到什么、什么仍未证明，
> 见文末「第三阶段 D 执行状态（2026-09-17）」。

潜在节省来自停止大量后续策略推理，不只是加快一次前向。实现风险与验证成本高于 C，先做固定根原型，再考虑采集。

- 现有拉面 flat search 要求 max_depth=0；已有 NN leaf evaluator 是温泉专用。需要真正实现拉面截断路径，不是开启已有配置即生效；仍使用模拟器，不自行猜协议或阶段机制。
- 明确定义从根起推进的完整回合数，而非绝对 turn 上限；截断只落在编码器支持、阶段与 pending 状态一致的决策边界。终局优先返回真实分数。
- 现有 value 标签是教师候选 rollout 的 cross-fit 结果，不是专门拟合的 V^NN。不能默认预测值就是“后续一直由 NN 接管”的真实期望；应在 NN 到达的叶状态测校准、候选差值误差与排序能力。
- value[0] 是终局总分估计，反归一化后不能再重复加当前累计分数。初次探索建议单设均值目标的完整续跑参考臂，比较短程/完整续跑的候选排序，不能宣称复刻 rf=1.4。
- 对叶预测均值再做排名加权会丢掉截断后随机性；对 value[2] 再排名加权也不等于原终局分布。mean/stdev/weightedMean 三个数不足以恢复完整分布，不能未经验证假设正态或把 stdev 当模型置信度。
- 少量预先固定的深度比较速度与误差；具体深度、可截断阶段在实现前确认。全续跑保留为参考；混合叶估值与全续跑的方案须另定明确估值口径。
- 若现有 value 排序不可靠，优先补 NN 自身续跑的叶状态标签并校准/重训 value；可保留 754/245 契约。不能靠增加根采样数消除系统性叶估值偏差。

### E：按候选不确定性分配预算（备选，晚于 C/D 的最小实验）

### D.2.5 value 的边界（两轮共同结论）

- **绝对偏差与候选排序偏差是两件事，必须分开**。绝对低估条件性、随回合收缩、
  **不是尺度封顶**（CPU 侧实测 `value.mean ∈ [62941, 67891]`）；共同偏移基本被 argmax 吃掉。
  排序偏差才是决定动作的那一项。成因**仍未定位**。
- 候选子集诊断（`logs/leaf_hybrid_y3_0917/run01/subset/`）**只用了两个既有 Y3 根，
  不是新增的独立验证**。口径：四个估值器的每候选数值只依赖该候选自己的样本，
  换子集不改估值、只改 argmax 竞争范围 ⇒ 量的是「误差被选中的概率」，不是估值精度。
  结论：**分歧率随子集增大单调升到 1.000 是主驱动，分歧时的条件损失并不随规模上升**。
- ❗**少候选也可能选中被高估的动作**：子集大小 5 时平均损失已有 508.7 / 293.1。
- ❗**增大 n 能减轻采样噪声，不能自动消除 value 的系统性偏差。**
- 仍然**分不开**「候选数」与「地区 × Y3」：本数据里 120 候选只在地区 Y3 出现过。

## E.5 任务四：专用叶 value 试采（待独立授权）

先固定 continuation policy π、规则、Score 公式、事件策略和比赛守门。
目标为 `Vπ(s) = E[真实终局 Score | 从叶状态 s 按固定 π 续跑]`，不是手写教师 best 候选的价值。
现有 cross-fit value 是“其余列选候选、留出列评价”，不是自动等于 Vπ，故不能原样混成同目标。

- 叶状态来自真实 H8 搜索轨迹，覆盖不同年份/阶段/构成、各候选分支及困难反例，
  不只采赢者，也不把同一轨迹的连续状态当独立验证样本。
- 每状态从已知当前局面条件下采未来随机续跑，完整跑到终局；固定状态的重复轨迹
  不能误当独立世界。要先核实游戏隐含状态、已揭示信息、turn_fixed 等条件随机性语义。
- 先小试估方差、标签标准误与成本，再确定重复次数；不默认全部 4096。
- 保留根/候选/轨迹/模型与规则身份、有效掩码和配对种子语义；能保留的 CRN 必须保留，
  不能强行共享已不满足同条件语义的随机状态。元数据用明文身份与实际字段，不引入哈希。
- 训练/验证按组合与同源轨迹分组隔离，既有最终留出继续排除。
- 新 value 数据单独版本和目录，不改旧 policy 数据格式；754/234/245 契约不变。
  具体侧车字段先出 schema 与读取测试，再经 review 开正式采集。
- 第一目标是 value[0] 真实均值；未重新标定的另外两路不得伪称新策略的有效估值。
- 旧 policy 数据保留；不同策略/规则的旧 value 需显式隔离，不能自动等权混训。
