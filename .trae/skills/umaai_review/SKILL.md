# umaai_review · 单局复盘归因

> 计算下沉到 Rust（`umaai_review` bin），判断力留给本 skill。
> 口径速查见 `reference/metrics_glossary.md`。
> 拟人化口吻是**可选覆盖层**：仅当 `reference/persona.md` 存在时启用（可删可改，
> 缺失时按默认平实专业口吻输出，流程与检查项不受影响）。

## 工作流程

### 1. 定位局包

两种来源：用户给的**路径**（如 `logs/game6234.zip`），或用户在聊天框**直接上传 /
拖入**的文件（按会话中收到的上传文件路径处理）。确认文件存在再进入下一步；
用户没指名时，`logs/` 下的历史 `game*.zip` 取最新一个。

### 2. 运行分析引擎

```powershell
# 开发期（workspace 内）
cargo run --release -p umaai_review -- --zip logs/game6234.zip
# 或直接调用编译产物
target\release\umaai_review.exe --zip logs/game6234.zip [--gamedata <path>]
```

产物落在局包同级目录 `logs/game{id}/`：`digest.json`（紧凑 JSON，喂归因）+ `report.html`（网页报告，只给路径不粘贴）。

- gamedata 自动解析顺序：`--gamedata` > `UMAI_DATA_DIR` > 局包向上找 `gamedata/` > cwd。全找不到时 bin 会降级（纯 ID、无评分），此时**询问用户一次** gamedata 位置，确认后写入本 skill 目录 `local_paths.json`（`{"gamedata": "..."}`），下次先读它再传 `--gamedata`。
- **降级路径**：exe 不可用时，用 `Expand-Archive` 解开局包，直接读 `decisions.csv` + `meta.json` 做决策链路 / 运气分 / 置信度分析（丢失依赖快照时序的检查项，结论需注明降级）。

### 3. 读取 digest.json

块导航（字段口径见 glossary）：

| 块 | 用途 |
|---|---|
| `meta` | 马娘 / 卡组 / 评分等级 / 终局运气分 / 结束方式 |
| `timeline` | 每回合快照状态（五维、体力、干劲、剧本 PT、缺席人物） |
| `decisions` | 每个决策点的候选 / 选中 / 期望分 / 回合Δ / 链长 |
| `execution` | AI 建议 vs 实际执行（动作推断 + 状态差证据） |
| `luck` | 运气分序列 / top_gain / top_loss / flagged_turns（伪波动） |
| `schedule` | 必赛回合 / 自由比赛区间与实跑 |
| `inherit` | 继承质量（贡献 vs 参考值） |
| `clones` | 分身彩圈观测（A/B 类，luck/strategy 来源） |
| `coverage` | skip 分原因 / unparsed / parse_error |
| `findings` | bin 自动产出的检查项命中清单 |
| `context` | 口径前提（必读，解读前先过一遍） |

### 4. 按检查项归因（框架）

每个检查项统一格式（后续增补照此追加，不动框架）：

```
### <检查项名>
- 判据：<什么情况算命中>
- 取数：<读 digest.json 的哪些字段>
- 输出：<结论格式 / 表格列>
- 状态：<已实现 / 待实测调整>
```

**bin 已自动产 findings（读 `findings` + 对应数据复核即可）**：

| 检查项 | 判据 | 取数 | 状态 |
|---|---|---|---|
| 目标赛未跑赢 | 必赛回合不在 raceHistory（只记跑赢） | findings / schedule.notes | 已实现（已验证） |
| 关键资源过早耗尽 | 友人次数达上限距结束仍远 + 此后体力低点 | findings / timeline | 已实现（已验证） |
| 心情掉落后未及时恢复 | 干劲下降后 3 回合无出行/休息且未回升 | findings / timeline | 已实现（已验证） |
| 训练失败候选 | AI 建议训练 + 五维零增长 + 体力有消耗 | findings | 候选清单，**人工复核**事件影响 |
| 超级拉面期盈亏 | turn≥72 回合合计Δ 正负（B 类分身机制保证落位，没吃到不算亏） | findings / luck | 已实现（已验证） |
| 执行偏离 | ai_choice ≠ actual_action | findings / execution | AIRedirector 局仅作校验、不产生结论 |

**归因口径提醒（用户拍板）**：目标赛未跑赢、超拉期连亏、以及掉干劲本身，都是
**运气导致的，不是操作**——输赛结果是随机的，掉干劲是输赛带来的，超拉期估值
走低是随机落地差；叙事时归入运气，不要表述成操作失误或坏手法。唯一例外是
「掉干劲后未主动恢复」：成因是已知偏差②（模拟高估事件回复、AI 不主动恢复），
表述为观察项与策略改进方向，同样不数落玩家。

**叙事归因项（LLM 结合 digest 判读）**：

- **运气极值归因**：对 `luck.top_gain` / `top_loss` 的回合分类（基础训练分布好 / 事件 / 吃面落地 / 地区效果）。`flagged_turns` 里的回合（年界 / 继承 / RMJ）**降级或跳过**——是程序性波动不是真实损益；注意 turn_delta 是「期望终局分」变化不等于属性增量，同回合多段以合计观察。
- **继承质量**：`inherit` 偏差为负 → 继承质量偏弱（用户已确认：是确实的损失，表述不要打折）。
- **分身观测**：`clones` 中 `rainbow_luck` 归好运、`rainbow_strategy` 归好策略；A 类其余分身主要价值是加人头（不是彩圈）。
- **运气总分解读**：支援卡事件进度未统计 → total_luck_end 略低于实际运气；`< -2000` 仍可判「这局运气差」。
- **判据待实测项**（有数据无判据，谨慎下结论）：训练与体力健康、吃面节奏、友人完成度、free_race 次数与时机、状态健康、属性溢出。

**通俗化叙事问题清单（复盘必须回答的问题，顺序即叙事骨架）**：

| # | 问题 | 取数 | 通俗化要点 |
|---|---|---|---|
| 1 | 这局总体打得怎么样？ | `meta`（评分/等级/结束方式）、`execution` 一致率 | 一两句话定调；评分仅供参考（略低于小黑板、未计「努力家」）口径要带 |
| 2 | 总体运气走势如何？ | `luck.series` 形态、`flagged_turns`、`total_luck_end` | 分段叙事（开局 / 中段 / 末期 / 超拉期）；伪波动段降级读；提醒 total_luck_end 略低于实际运气，< -2000 才判「运气差」 |
| 3 | 运气最好 / 最差的回合发生了什么？ | `luck.top_gain` / `top_loss` → 回到该回合的 `decisions`（吃了什么面 / 训练目标 / 候选差距）、`timeline`（事件前后状态差）、`clones`（分身彩圈 luck/strategy） | 每个极值回合一段叙事：具体操作 + 落地证据；flagged 回合注明「程序性波动，不作真实损益读」 |
| 4 | 继承质量如何？ | `inherit`（贡献 vs 参考值） | **表格 + 描述**：小表（回合 / 贡献 / 偏差）+ 一句话判断（偏优 / 正常 / 偏弱；偏弱是确实的损失，表述不打折） |
| 5 | 还有哪些操作或局面影响了运气波动？ | `luck.series` 显著段（top5 之外的转折）、`clones`、`execution` 偏离、`schedule` | 把波动归到**具体操作**（吃面 / 地区选择 / 训练目标）或**局面**（事件 / 分身落地 / 必赛）；能区分「操作导致」vs「随机」就分开说 |
| 6 | 建议被执行了吗？ | `execution` + `findings` 偏离 | 逐条给证据；默认称「AI 建议」，persona 启用时改称**理事长自己的建议**（第一人称「我当时的建议」）；AIRedirector 局只作校验，不数落 |

### 5. 输出

- **叙事归因结论**：只在对话输出，不落盘。
  - 默认口吻：**通俗说法 + 马娘玩家术语优先**——读者懂游戏与 `reference/metrics_glossary.md`
    里的术语，优先用玩家熟悉的说法：彩圈 / 友情训练 / 羁绊 / 干劲 / 体力 / 吃面 /
    超级拉面 / 目标赛 / URA 决赛 / 继承（因子）/ 出行 / 友人卡……少用内部字段名
    （`turn_delta` 说成「运气波动」，`T(n)` 说成「期望评分」，`flagged_turns` 说成
    「程序性波动回合」）。
  - 表达习惯：**少用括号与破折号**——补充说明、数据口径、回合号用连接性语句
    自然带出，融进句子里（例：「终局 62500，评价 UA9。顺带一提，这个评分口径
    仅供参考，实际还要略高一点」），不要堆「（UA9，仅供参考）——」式插入语。
  - 语气基调（按结局定调，先于其他语气规则）：**评级达 LG 档（final_score
    ≥ 76000）就是很好的局面**，以鼓励为主；坏局要**减弱负面性描述**——运气
    分只属于这一局，下一局运气可能更好，给读者留希望；若坏局的根因是**继承
    质量偏弱**（结构性、局外因素），稍微提一下即可，不深究、不责备。
  - 篇幅纪律：**原因分析简明**——每条发现先用一两句话点出原因、切中要点，
    不长篇大论；**额外的判据、口径说明、待定项不穿插在分析中间**，统一放到
    结尾一小节再提。
  - 可选：若 `reference/persona.md` 存在，按其口吻呈现（如秋川理事长：对部下
    训练师的亲切建议；术语偏好与表达习惯不变）。人设文件可删可换——**无论有无，
    数据与结论必须与 digest 一致**，拟人化只改表达层。persona 启用时，digest 的
    `execution.ai_choice` **统一改称理事长自己的建议**（第一人称「我当时的建议」），
    叙事中不出现「AI」字样——部下采纳与否就成了对理事长建议的回应。
- **网页报告**：对话中给出 `report.html` 路径，不粘贴内容。
- 结构建议 = 通俗化问题清单的顺序：概况（Q1）→ 运气走势（Q2）→ 极值回合叙事（Q3）→ 继承表格+描述（Q4）→ 其他波动来源与坏手法（Q5 + findings）→ 改进建议 → **末尾集中一小节放额外判据与口径备注**（待定项、读数须知等）→ 报告路径收尾。
